## Shipped today

### `41594cc` — production LLM client

14 files, ~2,600 lines. Sits behind the `LLMProvider` port that already existed, so the categoriser,
hybrid, metrics, and report are unchanged. That was the point of building the port first.

| Module | What it does |
|---|---|
| `errors.py` | Error taxonomy split by whether retrying can help. Includes `529` (Anthropic overload) — not a standard status, and a client that only knows 5xx calls it fatal and fails the batch. |
| `transport.py` | `Transport` port + stdlib `urllib` implementation + `FakeTransport`. The seam that makes everything testable offline. |
| `retry.py` | Full jitter, `Retry-After` honoured over our arithmetic, wall-clock deadline. Injected `Clock` so tests don't sleep. |
| `prompts.py` | Prompt as a versioned artifact (`categorise/v1`), tool schema with the label space closed by an enum. |
| `anthropic.py` | The adapter. Structured output via forced tool use, temperature 0, key redacted from `__repr__`. |
| `factory.py` | Builds from settings; returns `None` rather than raising when no key exists. |
| `llm_smoke.py` | Offline mode prints the exact bytes that would be sent; `--live` makes one real call. |

**Found by running it rather than trusting the tests:** every fixture used the label `DINING`, which
is not in the taxonomy — the real one is `LIVING_DINING`. The tests passed anyway, because the
provider deliberately leaves label validation to `LLMCategoriser`. The fixture error was the
symptom; the actual gap was a missing test at the seam between the client and the harness. That test
now exists, and it documented something worth keeping: `UNKNOWN` is both a valid label and the
abstention sentinel, which lets a model decline *inside* the schema instead of guessing.

## Decisions recorded today

**The package stays `offerdelta`.** Renaming would touch every import, the Alembic config, the
Render service definition, and the live demo URL — no behaviour change, real chance of breaking a
working deployment. Documented in the README's *A note on naming* so it reads as a decision rather
than neglect. Only uncoupled text changed: OpenAPI title, page title, package description.

**The offer comparison is a scenario, not a separate product.** The taxonomy already implied it —
`RELOCATION_*` and `COMMUTE_*` exist because the engine answers relocation questions.

**A partial evaluation can never be quoted as a benchmark.** `--limit N` records `[:N]` in the
dataset version, and it appears in the report header.

## The data-safety pass

A review of `e51562c` found the fingerprint built from three unnormalised inputs, each of
which broke deduplication on its own: an un-quantised amount scale, a case-sensitive
free-text account, and an unversioned merchant heuristic. Two were confirmed empirically —
`-4.50` and `-4.5` stored twice, and `--account=Checking` versus `--account=checking` built
two parallel copies of a statement.

The corrective pass canonicalises account identity behind a registry, makes the fingerprint
quantised and versioned and reproducible from persisted fields, replaces the hand-rolled CLI
parsing with argparse behind an explicit `--yes` gate, and separates snapshot from incremental
import semantics rather than guessing between them.

The ambiguity at the centre is worth stating plainly: a fingerprint plus a per-file occurrence
number cannot distinguish a genuine third identical charge from one already stored, because
the deciding fact is not in the file — it is a fact about how the file was produced. So the mode
is declared, and incremental mode refuses to run without a bank transaction id rather than pick
a reading silently.

Verification: 1006 tests, five checks green (format, lint, strict types, both architecture
contracts, tests). The pass adds one more migration, `3dfb104aabcb`, which destructively rebuilds
`transactions` on the corrected identity model — the old fingerprints predate versioning and
cannot be recomputed, only rebuilt. It is applied to the configured PostgreSQL database, which
currently holds zero accounts, batches, or transactions. None of this is deployed.
