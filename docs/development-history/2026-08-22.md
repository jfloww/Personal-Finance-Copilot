## The ASCII-only account key

Yesterday's canonical key used `[^a-z0-9]+` after `casefold()`. Verified today:

```
k("Café Checking") -> 'caf-checking'
k("Caf Checking")  -> 'caf-checking'    same? True
k("저축")           -> ValidationError: needs at least one letter or digit
```

The collision is the exact failure the function exists to prevent — two distinct
names becoming one account — arriving through an accent instead of a case
variant. The rejection means an account could not be named in the owner's own
language.

Fixed with NFKC normalisation plus `str.isalnum()`. NFKC matters independently:
without it, "Café" typed with a composed `é` and with `e` + combining accent
would be two different accounts.

## What was got wrong today

**A ruling caused a scope explosion.** Task 6 was asked to decouple persistence
*and* align a grouping key with the fingerprint. The second half sent the work
into factoring a shared helper across two modules — one of which a later task
rewrote wholesale anyway. The attempt died mid-refactor, leaving the tree broken
and, worse, having already flipped the import-linter contract to green: the
red-green evidence was spent without being recorded.

All of it was discarded and the task re-run with the alignment deferred. The
lesson is narrow and repeatable: **a task that both restructures and optimises
will do neither well.**

**An interim fix broke the CLI write path.** Scaffolding written to keep mypy
green produced a ~37-character key for a `String(32)` column, and
`preview_import.py` still called that method. Caught by review; would have
failed at insert.

**A guarantee was column-level when it needed to be row-level.** Incremental
mode checked once that an id *column* existed, then set `external_id = None` per
row whenever that cell was blank — so a sparse id column would let those rows
back into exactly the ambiguity the mode refuses. A realistic bank-export shape.

## Ruling

**Disable `preview_import.py --commit` outright** rather than fix its window.
Its import window was derived from the file's own rows, so it could never reject
anything — a documented-inert guarantee on the one path that writes to a live
database, in a file excluded from both mypy and CI's linter.

A lock that does not engage is worse than a closed door. Cost if wrong: the old
CLI could not commit for three tasks, while nothing real was being imported.
